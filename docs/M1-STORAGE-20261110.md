## Implementation and boundaries

The [module guide](../metadata_engine/storage/README.md) and
[file-format specification](../metadata_engine/storage/FORMAT.md) describe the
database, format/recovery, ordered tree/cache, transactions, commit worker and
checkpoint modules. Production modules have explicit responsibilities; the
service adapter remains in `metadata_engine/src/store.rs`.

The implementation uses an ordered copy-on-write disk tree, bounded node cache,
concurrent snapshot readers and optimistic transactions with point/range
validation. Compatible commits share a synchronization boundary. Publication
and successful ACKs follow synchronization. A checkpoint copies a pinned view,
replays concurrent commits and durably switches generations; readers retain
their old generation until release. Values are not retained in a whole-database
RAM catalogue, and no per-object database files are created.

Procyon, Fjall, lsm-tree, SurrealKV and SQLite are absent from M1's dependency
graph. The core's normal dependencies are CRC32C, libc and UUID generation.
[SQLite source-study notes](../metadata_engine/storage/SQLITE-NOTES.md) record
the reference material and applied recovery invariants. No SQLite source or
database implementation is incorporated.

### Failures found and corrected

The initial database shutdown path relied on the last close to release its
process lease. A concurrent fork could inherit that descriptor and keep it
locked after the owner finished. Shutdown now drains workers and explicitly
unlocks; snapshots and iterators still retain ownership until release. A
duplicate-descriptor regression verifies subsequent reopen.

Large queued transactions could collectively exceed the on-disk group bound.
The coordinator now defers the next request before combining it into an
oversized group. A deliberately saturated queue of near-limit keys verifies
all acknowledged transactions after reopen.

An added length-corruption test fails against the experimental 24-byte record
header: a damaged length extending past EOF could be treated as an unfinished
append. The final format has a **28-byte header with an independent CRC32C**,
validated before trusting that length. All 32 length-bit flips must fail without
changing evidence; the genuine incomplete-tail sweep still recovers the prior
transaction. Final candidates use fresh databases; earlier experimental
database files and binaries remain preserved separately.

The API fixture also required two corrections. Functional archive checks hit
N1's default read quota; those fixtures now explicitly disable N1 quotas while
the dedicated admission tests retain their explicit policy. This does not
change production quotas. A closed port probe could receive the same port
twice before either server started; the helper now keeps allocated ports
distinct within its process. The initial candidate-09 TLS setup failure and
successful continuation remain in the raw logs.

The missing Accel prerequisite was resolved by building the real, unchanged
Accel source. GNU time was unavailable, so the drivers use Bash's whole-job
`time -p`; RSS is separately sampled by the Rust workload. Private-fixture
permission/setup failures remain recorded and are excluded from pass counts.
The subsequent HDD USB/XFS fault interrupted the physical benchmark; no repair
or filesystem changes are attempted to turn it into a pass.
