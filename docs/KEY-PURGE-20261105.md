# Key lifecycle qualification — November 5, 2026

The current contract is defined in [NOA.md](../NOA.md) and
[LINK-FORMAT.md](LINK-FORMAT.md). This record covers its implementation and
testing; it does not introduce a second architecture specification.

Begin, continuation and finalization use the same `N1A1.` LINK key. Begin is
the only operation allowed to allocate incomplete shards. Purge persists removal
of incomplete/final/repair files and identity staging directories, with no
terminal files or permanent object-side deletion state. Old continuation after
successful purge is 404 and cannot recreate the upload.

Begin acknowledges allocation. The operator selected persistence with the first
durable payload: an unused allocation may disappear on power loss and its old
key then returns 404. A durable part persists its header, payload and complete
staging ancestry before success. Normal/batch PUT and finalization persist the
header with durable publication. No extra unused-Begin flush is required.

The exact 3+1 interrupted-purge case has a SIGKILL regression using four logical
member directories on PROJECT: three final paths are removed, one remains,
the process is killed, GET/finalize refuse after
reopen, and retry removes the survivor. With K surviving shards an unacknowledged
partial purge can still be readable or repairable. Metadata retains its durable
reclamation claim and LINK key until native ACK and retries GC after restart;
a direct client retains its own unfinished deletion intent. Object startup
does not infer deletion intent from surviving files.

The optimized workspace run passed 472 tests with no failures and 36 explicit
opt-in/helper exclusions; 81 documentation cases and strict scoped Clippy passed.
All 13 selected two-HDD integration tests passed, covering
GC retries, cross-EC migration, member loss/corruption, metadata restore,
crash/resume, backup/replication and blank-member replacement. All three matched
mixed-workload ABBA benchmark campaigns passed complete readback and deletion
censuses. A separate ABBA campaign covers batch upload, standard/durable
multipart, reconnect/status, repeated finalize and bounded concurrent PUT.
The dedicated HDD purge suite passed 11 cases, including
128 churn cycles, old-key replay, allocation failure rollback, partial-member
failure, backup pinning and the exact SIGKILL boundary. These 11 are repeated
executions of default cases, not 11 additional distinct default tests. Five
persistence cases also passed on PROJECT, covering failed publication,
cancellation/drain, sparse missing parts after restart, lost unused allocation
and the first durable part's required staging ancestry persistence.

The implementation now keeps targeted file-data synchronization before normal
publication and joins namespace persistence per filesystem, including on
publication failure. Fresh payload writes establish the immutable shard length
sparsely, avoiding speculative XFS allocation beyond EOF. A Rust FIEMAP probe
verified no unwritten extents, less than one 4 KiB block of mapped EOF tail,
complete 1 GiB SHA-256 after restart, and zero identity paths after purge,
without external truncation. File length and holes never imply completion.

The pre-format mixed-workload comparison against previous LINK measured 100 small
uploads at 39.285 → 35.102 seconds and purge of 101 objects at 52.472 → 12.152
seconds. Large-upload results varied across runs; the report preserves each
sample and the focused repeated large-object comparisons. This is not a claim
that every performance row improved. CPU/RSS, latency, geometry, allocation,
cache and lifecycle differences are recorded with the measurements.
