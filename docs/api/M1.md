# M1 API reference and examples — NOA v1

M1 manages fragments, logical names, immutable versions, resumable uploads and
trash in its own specialized transactional database. Its object payloads go to N1 through native NOA v2.
Connect Console and named-object applications to **M1**, not N1's object port.
The [NOA standard](../../NOA.md) defines the contract; this guide describes the
current requests and responses. [N1's guide](N1.md) covers direct LINK access.

## Conventions and authentication

The shell examples use Bash, `curl` and `jq`, a prepared M1 → N1 deployment,
and plaintext loopback for a local example. Set `M1_BASE` to your public HTTPS
address for a deployed service. For a private CA, set `CURL_CA_BUNDLE` to its PEM
file. Listener/TLS configuration is in the [operator guide](../../DOCUMENTATION.md).

```bash
M1_BASE=${M1_BASE:-http://127.0.0.1:50001}
curl --fail-with-body --silent --show-error "$M1_BASE/noa/v1/ping"
```

HTTP 200:

```json
{"status":"ok","engine":"m1","version":"1.0.0-RC.2"}
```

`version` comes from the running binary. All response IDs, timestamps, secrets
and signatures below are illustrative; use values returned by your server.
Sizes and offsets are bytes. Part indices start at **zero**. Timestamps are Unix
seconds unless a field says otherwise. `object_key` is a logical name such as
`docs/hello.txt`; it is never a LINK key in M1's public named API.

Encode each path component when building a URL; preserve `/` separators in
object names. For example `docs/hello world.txt` becomes
`docs/hello%20world.txt`. Use `curl --get --data-urlencode` for query values.
Never concatenate an unescaped name, cursor or signed token into a query.

Protected calls use `Authorization: Bearer <access_token>`. Permissions are
independent: `read`, `write`, `modify`, `delete`. Omitted login permission flags
default to **false**. Maintenance mutations require write + modify + delete;
operator actions additionally require a token obtained using M1's master key.
The master key is not the Bearer token and is not an N1 object-service password.

## Create a fragment and log in

Read the deployment master key and a new fragment access key without placing
their literal values in shell history:

```bash
read -r -s -p 'M1 master key: ' M1_MASTER_KEY; printf '\n'
read -r -s -p 'New fragment access key: ' M1_FRAGMENT_KEY; printf '\n'
M1_FRAGMENT_NAME=api-example

created=$(jq -n \
  --arg name "$M1_FRAGMENT_NAME" --arg secret "$M1_MASTER_KEY" \
  --arg key "$M1_FRAGMENT_KEY" '{name:$name,secret:$secret,key:$key}' |
  curl --fail-with-body --silent --show-error \
    -H 'Content-Type: application/json' --data-binary @- \
    "$M1_BASE/noa/v1/fragments")
M1_FRAGMENT=$(jq -er '.fragment_hash' <<<"$created")
```

HTTP 201, response shape:

```json
{
  "fragment_hash":"<fragment-alias>",
  "fragment_id":"01M6TZ30FSRC9P2HX3G22CXYDR",
  "name":"api-example",
  "message":"Fragment created"
}
```

The stable `fragment_id` survives alias changes. Authenticate with the returned
alias or stable ID; M1 also resolves a configured logical fragment name.

```bash
login=$(jq -n --arg fragment "$M1_FRAGMENT" --arg secret "$M1_FRAGMENT_KEY" \
  '{fragment:$fragment,secret:$secret,read:true,write:true,modify:true,delete:true,expires_in:3600}' |
  curl --fail-with-body --silent --show-error \
    -H 'Content-Type: application/json' --data-binary @- \
    "$M1_BASE/noa/v1/auth/fragment")
M1_TOKEN=$(jq -er '.access_token' <<<"$login")
M1_REFRESH=$(jq -er '.refresh_token' <<<"$login")

m1() {
  curl --fail-with-body --silent --show-error \
    -H "Authorization: Bearer $M1_TOKEN" "$@"
}
```

HTTP 200, response shape:

```json
{
  "access_token":"<access-token>",
  "token_type":"Bearer",
  "expires_in":3600,
  "refresh_token":"<rotating-refresh-token>",
  "refresh_expires_in":604800
}
```

Actual lifetimes follow the service's configured policy. Refresh with
`POST /noa/v1/auth/refresh`, body `{"refresh_token":"<current-refresh>"}`.
Replace **both** stored tokens with the response. Refresh tokens are single-use;
reusing a rotated token revokes its refresh family. Logout uses the same body at
`POST /noa/v1/auth/logout` and returns `{"logged_out":true}`. Stop using the access
token after logout; it is stateless and otherwise lives until expiry or an
applicable fragment-epoch change.

## Upload, read and list an object

One-shot accepts a raw body, not a JSON envelope. A known Content-Length avoids
unknown-length spooling on the metadata host. The path names the logical object.

```bash
printf 'hello' > hello.txt
published=$(m1 -H 'Content-Type: text/plain' --data-binary @hello.txt \
  "$M1_BASE/noa/v1/upload/one-shot/docs/hello.txt?durability=strict")
M1_VERSION=$(jq -er '.version_id' <<<"$published")
```

HTTP 201:

```json
{
  "object_key":"docs/hello.txt",
  "object_id":"01M6TZ30FSRC9P2HX3G22CXYDS",
  "version_id":"01M6TZ30FSRC9P2HX3G22CXYDT",
  "content_type":"text/plain",
  "total_size_bytes":5,
  "created_at":1794040000,
  "created_at_unix":1794040000
}
```

This published-version shape is also returned by metadata lookup, multipart
finalization and successful batch entries. Re-uploading the same name publishes
a new immutable version; a lost one-shot response is not an idempotency token.
Use multipart session identity when retry-safe publication is needed.
Unpinned reads select the current max-ULID version. Retain `version_id` to keep
reading the same immutable version while another client publishes a newer one.

```bash
# Current metadata, version inventory, and a pinned immutable version:
m1 "$M1_BASE/noa/v1/objects/meta/docs/hello.txt"
m1 "$M1_BASE/noa/v1/objects/versions/docs/hello.txt"
m1 --get --data-urlencode "version_id=$M1_VERSION" \
  "$M1_BASE/noa/v1/objects/get/docs/hello.txt" --output downloaded.txt
cmp hello.txt downloaded.txt

# HTTP 206, Content-Range: bytes 1-3/5, body: ell
m1 -H 'Range: bytes=1-3' \
  "$M1_BASE/noa/v1/objects/get/docs/hello.txt" --output range.txt

m1 --get --data-urlencode 'path=docs' --data-urlencode 'limit=100' \
  "$M1_BASE/noa/v1/posix/list"
```

The last request returns HTTP 200:

```json
{
  "path":"docs",
  "scan_trash":false,
  "entries":[{
    "name":"hello.txt","path":"docs/hello.txt","kind":"file",
    "size_bytes":5,"modified_at_unix":1794040000,
    "content_type":"text/plain","version_id":"01M6TZ30FSRC9P2HX3G22CXYDT"
  }],
  "continuation_token":null
}
```

Directories are virtual prefixes. Continue listing with the opaque
`continuation_token`, keeping fragment, path and other selection settings
unchanged. An empty page is not sufficient to stop if a cursor is present.
`GET /objects` is the delimiter-based alternative; `include_metadata=true`
populates its `objects` array. Its lightweight `entries` fields currently carry
placeholder size/time values; use `objects` or `posix/list` for actual file metadata.

Named reads return a quoted **version ID** ETag, not N1's integrity-tree root.
Normal M1 origin reads support a single `Range` (including suffix/open-ended
ranges); this guide does not promise N1's full conditional-GET behavior for M1.
Download/chunk requests use query fields as listed below. A successful body must
reach its declared length; a 200 header alone does not prove transfer success.

Generate a scoped, version-pinned URL for a browser/player without exposing a
fragment token:

```bash
signed=$(m1 -H 'Content-Type: application/json' \
  --data '{"object_key":"docs/hello.txt","expires_in":300}' \
  "$M1_BASE/noa/v1/objects/signed-url")
curl --fail-with-body --silent --show-error \
  "$(jq -er '.url' <<<"$signed")" --output signed-download.txt
```

Response: `{"url":"<URL>","signed_url":"<same URL>","expires_at":1794040300,"expires_in":300}`.
The URL uses the incoming Host and configured HTTP/TLS mode; call M1 with the
address clients can reach. Its grant is capped at one hour and checks current
fragment epoch and object availability. Keep it private until expiry.

## Multipart upload and resume

Select `multipart/durable` for durable part ACKs. The standard `multipart`
family has identical URL suffixes and schemas, with `durability=strict` or
`durability=batched` controlling its part policy. Do not change the durability
mode of an existing session. Persist the handle and reselect the same local
source file after a browser restart; M1 owns server-side acknowledged progress.

Create a ten-byte object in two five-byte parts:

```bash
printf 'hello' > part-0.bin
printf 'world' > part-1.bin
handle=$(m1 -H 'Content-Type: application/json' \
  --data '{"content_type":"text/plain","total_size_bytes":10,"expected_parts":2,"part_size_bytes":5}' \
  "$M1_BASE/noa/v1/upload/multipart/durable/init/docs/multipart.txt")
M1_UPLOAD_VERSION=$(jq -er '.version_id' <<<"$handle")
M1_SESSION=$(jq -er '.session_id' <<<"$handle")
M1_UPLOAD="$M1_BASE/noa/v1/upload/multipart/durable/$M1_UPLOAD_VERSION"

m1 -X PUT --data-binary @part-0.bin "$M1_UPLOAD/0"
# Reconnecting or reloading the client does not cancel this upload.
m1 "$M1_UPLOAD"
```

Init returns HTTP 200:

```json
{
  "version_id":"01M6TZ30FSRC9P2HX3G22CXYDV",
  "session_id":"01M6TZ30FSRC9P2HX3G22CXYDW",
  "object_key":"docs/multipart.txt",
  "total_size_bytes":10,"part_size_bytes":5,"expected_parts":2,"durable":true
}
```

The part reply is `{"version_id":"<version>","part_index":0,"uploaded":true}`.
Status after part zero returns:

```json
{
  "version_id":"01M6TZ30FSRC9P2HX3G22CXYDV",
  "session_id":"01M6TZ30FSRC9P2HX3G22CXYDW",
  "object_key":"docs/multipart.txt",
  "total_size_bytes":10,"part_size_bytes":5,"expected_parts":2,
  "uploaded_parts":[0],"committed_parts":1,
  "uploaded_bytes":5,"committed_bytes":5,"completed":false,"durable":true
}
```

Compute missing indices as `0..expected_parts-1` minus `uploaded_parts`. Transfer
only missing parts, then finalize with a JSON body (an empty object is accepted):

```bash
m1 -X PUT --data-binary @part-1.bin "$M1_UPLOAD/1"
m1 -H 'Content-Type: application/json' --data '{}' \
  "$M1_UPLOAD/$M1_SESSION/finalize"
# Same session and body: retry finalization after a lost reply.
m1 -H 'Content-Type: application/json' --data '{}' \
  "$M1_UPLOAD/$M1_SESSION/finalize"
m1 --get --data-urlencode 'limit=25' \
  "$M1_BASE/noa/v1/upload/multipart/durable"
```

Finalize returns HTTP 200 with the published-version shape. Completed uploads
leave the resumable inventory. Listing returns `{"sessions":[<handles>],
"continuation_token":null}`. Standard and durable inventories are separate.
Repeating init with the same name, content type, geometry and durability can
reuse an unfinished session; `?fresh=true` explicitly requests a new one.

After an engine restart, M1's durable ACK index still supplies resume status
without reading object payloads. If N1 reports that volatile completion must be
reconciled, M1 checks existing parts through bounded status pages before one
finalize retry. This exceptional recovery can take longer than healthy
finalization; it does not retransmit payloads or create a replacement identity.
Missing or purged data remains an error, never a successful publication.

Cancel an unfinished upload with `DELETE "$M1_UPLOAD"`; response is
`{"cancelled":true}`. Cancel is different from closing/reloading the client.
A cancelled plan returns 410; cancelling a completed publication returns 409.

`expected_parts` must equal `ceil(total_size_bytes/part_size_bytes)` for nonempty
objects. M1 represents an empty multipart object as one zero-byte external part.
Every non-final part has `part_size_bytes` bytes; the last has the remainder.
The current external part-count limit is 131,072, and configured `max_part_size`
limits each part. The optional file-size policy is independent of that limit.
Larger files need appropriate part geometry, not one part per byte or an
unbounded in-memory buffer. M1 bridges unaligned client parts through bounded
disk staging; stripe-aligned parts can avoid that re-chunking step.
The bridge verifies staged checksums before forwarding payload to N1. Its
transfer buffers share `upload_memory_budget_bytes` with batch uploads. If
that budget is busy, a part can return 503 without an acknowledgement; retry
the same version, part index and bytes after pressure subsides. Bridged
finalization still forwards staged payload; it does not inherit N1's
O(pool width) finalization cost.

Clients can avoid that staging by opting into part-size negotiation on **init**:

```json
{
  "total_size_bytes": 1073741824,
  "expected_parts": 128,
  "part_size_bytes": 8388608,
  "negotiate_part_size": true
}
```

For a pool with three data shards and 256 KiB blocks, M1 returns
`part_size_bytes: 7864320` and `expected_parts: 137`. These returned fields are
authoritative: slice the source and construct the finalize body using them.
The input count must still describe the requested hint correctly. M1 chooses
the geometry before allocating the LINK identity, respects `max_part_size`,
and increases the part size when needed to stay within 131,072 parts. It does
not change the file-size policy or allocate a buffer the size of an object.
If the configured part limit cannot hold one native stripe, M1 retains its
bounded staging adapter instead. Empty uploads retain their single-part rule.

Repeating the same pending init hint returns the saved identity **and saved
geometry**, including after a restart. Resume never renegotiates an existing
version. Omitting `negotiate_part_size`, or setting it to `false`, keeps the
exact caller-supplied shape and its existing validation. Native `multipart.init`
accepts the same optional field. Direct LINK clients and N1 are unchanged.

## Batch upload

Use multipart/form-data fields named **`object`**. Their filename is the logical
key, percent-encoded when needed. Each object is at most 1 MiB; a request contains
at most 4,096 objects. Split large folder inventories into bounded batches.

```bash
m1 -F 'object=@hello.txt;filename=docs%2Fbatch-hello.txt;type=text/plain' \
  -F 'object=@part-1.bin;filename=docs%2Fbatch-world.txt;type=text/plain' \
  "$M1_BASE/noa/v1/upload/batch?durability=strict"
```

All-success returns 201; mixed results return 207. Inspect each result, not just
the HTTP status. Successful rows contain the published-version fields plus
`status:201,success:true`; failures contain `object_key,status,error`.

```json
{"results":[{"object_key":"docs/bad.txt","status":400,"error":"<reason>"}],"uploaded":0,"failed":1}
```

This is a response-shape example, not the expected result for the valid batch
above. There is no durable-batch route. The retained `concurrency` query accepts
1..128, but current batch grouping chooses its own bounded service path; it is
not a promise of that many simultaneous object writes. Already completed batch
entries are not rolled back if a later entry/body fails. Retrying one-shot/batch
names can create another version; reconcile successful entries before retrying.

## Rename, trash and recover

These operations mutate M1 metadata. They do not rename or relocate N1 shards.

```bash
m1 -H 'Content-Type: application/json' \
  --data '{"source_path":"docs/hello.txt","destination_path":"docs/renamed.txt"}' \
  "$M1_BASE/noa/v1/posix/rename"
trashed=$(m1 -X DELETE "$M1_BASE/noa/v1/objects/docs/renamed.txt")
M1_TRASH_ID=$(jq -er '.trash_entry_id' <<<"$trashed")
m1 "$M1_BASE/noa/v1/trash?limit=100"
m1 -H 'Content-Type: application/json' \
  --data "$(jq -n --arg id "$M1_TRASH_ID" '{path:"docs/renamed.txt",trash_entry_id:$id}')" \
  "$M1_BASE/noa/v1/posix/recover"
```

Rename returns HTTP 200:

```json
{
  "operation":"rename","kind":"file","affected":1,"affected_paths":1,
  "source_path":"docs/hello.txt","destination_path":"docs/renamed.txt",
  "conflicted_paths":[],"failed_paths":[]
}
```

Trash returns `operation:"trash"`, file/directory `kind`, counts, a
`trash_entry_id`, and failure/conflict arrays. Recover returns
`operation:"recover"`, counts and failure/conflict arrays. Inspect these arrays
even when HTTP is 200: prefix and bulk operations have per-child outcomes.
Cross-fragment rename is rejected. A destination conflict does not overwrite
another object. After trash TTL expires, metadata GC reclaims versions through
N1's delete API; it is then too late to recover from trash.

## Archives and export jobs

Direct archive requests return a streamed archive, not a JSON job. A retained
export returns a job first and a stable artifact after it becomes ready.

```bash
m1 -H 'Content-Type: application/json' \
  --data '{"keys":["docs/renamed.txt"],"format":"zip","filename":"selected.zip"}' \
  "$M1_BASE/noa/v1/objects/archive" --output selected.zip

# Plain UTF-8 lines: KEY, or VERSION_ID<TAB>KEY. This is not NDJSON.
printf 'docs/renamed.txt\n' > archive-manifest.txt
m1 -H 'Content-Type: text/plain' --data-binary @archive-manifest.txt \
  "$M1_BASE/noa/v1/objects/archive/manifest?format=tar&filename=selected.tar" \
  --output selected.tar

export_job=$(m1 -H 'Content-Type: application/json' \
  --data '{"keys":["docs/renamed.txt"],"format":"tar","filename":"retained.tar"}' \
  "$M1_BASE/noa/v1/exports")
M1_EXPORT_ID=$(jq -er '.export_id' <<<"$export_job")
m1 "$M1_BASE/noa/v1/exports/$M1_EXPORT_ID"
```

Export creation returns HTTP 202:

```json
{
  "export_id":"01M6TZ30FSRC9P2HX3G22CXYDX","phase":"queued",
  "status_url":"/noa/v1/exports/01M6TZ30FSRC9P2HX3G22CXYDX",
  "download_url":"/noa/v1/exports/01M6TZ30FSRC9P2HX3G22CXYDX/download",
  "expires_at_unix":1794126400
}
```

Poll the status at a bounded interval until `ready`, `failed` or `cancelled`.
Intermediate phases are `queued`, `capturing_manifest`, `building`. Status
includes object/source/artifact byte counters and optional error. A ready record
adds `artifact_size_bytes`, an artifact SHA-256 `etag`, and `download_url`.
Download before ready returns 409; expired records return 410.

```bash
# This small example waits up to 60 polls; use your application's job deadline.
for attempt in $(seq 1 60); do
  state=$(m1 "$M1_BASE/noa/v1/exports/$M1_EXPORT_ID")
  phase=$(jq -er '.phase' <<<"$state")
  case "$phase" in
    ready) break ;;
    failed|cancelled) printf '%s\n' "$state" >&2; exit 1 ;;
  esac
  sleep 1
done
test "$phase" = ready || { printf 'Export is still pending\n' >&2; exit 1; }
m1 "$M1_BASE/noa/v1/exports/$M1_EXPORT_ID/download" --output retained.tar
m1 -H 'Range: bytes=0-1023' \
  "$M1_BASE/noa/v1/exports/$M1_EXPORT_ID/download" --output artifact-prefix.bin
m1 -H 'Content-Type: application/json' --data '{"expires_in":300}' \
  "$M1_BASE/noa/v1/exports/$M1_EXPORT_ID/signed-url"
# Explicit cancellation; does not delete source objects:
m1 -X DELETE "$M1_BASE/noa/v1/exports/$M1_EXPORT_ID"
```

Selections support `keys`, `entries`, `prefix`, `prefixes`, `export_all`,
`format` (`zip` default or `tar`) and `filename`. Each `entries` item requires
`object_key,archive_path`, with optional `version_id,offset_bytes,length_bytes`.
Archive paths must be safe relative names. `include_internal=true` is rejected.
Retained selection limit is 4,096; direct selection limit is 10,000 and JSON
body limit is 4 MiB. Direct prefix/all selections or more than 1,000 explicit
entries use TAR even if ZIP was requested. Manifest streaming supports TAR only,
with an 8,192-byte line limit and body-idle timeout. Direct archive streams have
no stable length/range resume; use retained artifacts for resumable downloads.
The `[export]` INI section controls `retention_seconds`,
`cleanup_interval_seconds`, `max_retained_bytes`, `max_queued_jobs`,
`max_concurrent_jobs` and `max_concurrent_downloads`. A zero retained-byte limit
means unlimited. Builds reserve capacity before writing artifacts; capacity
refusal leaves source objects intact. Queue or download saturation returns 503.
Expired jobs return 410 until indexed cleanup removes their retained state,
after which they return 404. An already admitted download retains its files
until its reader finishes. Cancellation expires the retained artifact without
deleting source objects. Restart admission is paced through the bounded queue.
See the [qualification evidence](../RC2-HANDOVER-20261111.md) for completed
checks and the [release checklist](../RC2-IMPLEMENTATION.md) for remaining gates.

## Monitoring, maintenance and backups

Routine monitoring uses cached observations; it does not trigger payload scans.
M1 and N1 component observations identify their own nodes and sample ages.

```bash
m1 "$M1_BASE/noa/v1/maintenance/health"
m1 "$M1_BASE/noa/v1/maintenance/pools/health"
m1 "$M1_BASE/noa/v1/capacity/fragment"
# Explicit scan admission, then poll without re-starting the scan:
m1 "$M1_BASE/noa/v1/maintenance/pools/health?deep_scan=true"
m1 "$M1_BASE/noa/v1/maintenance/pools/health?deep_scan=false"
# Object-specific checksum check:
m1 "$M1_BASE/noa/v1/objects/status/docs/renamed.txt?mode=checksum"

# Observe TTL-eligible metadata GC work without purging:
m1 -X POST "$M1_BASE/noa/v1/maintenance/gc/start?dry_run=true"
m1 "$M1_BASE/noa/v1/maintenance/gc/status"
# Check integrity without healing:
m1 -X POST "$M1_BASE/noa/v1/maintenance/repair/start?mode=check"
m1 "$M1_BASE/noa/v1/maintenance/repair/status"
```

Maintenance starts return HTTP 200 with a persisted job, not an assertion of
completion. Status includes `id,kind,phase,request,started_at_unix,
updated_at_unix,scanned,processed,bytes_processed,failures,deferred,last_error`,
plus `running,policy,owner`. Before any job, status has `phase:"idle"` and policy.
Running jobs progress to `completed`, `stopped` or `incomplete`; `stopping` and
`interrupted` are nonterminal. A deferred or incomplete check is not proof of
corruption. GC always enforces configured trash TTL; there is no TTL bypass.

To migrate between enrolled pools, use **pool IDs**, not their INI letters:

```bash
# Set these from your enrolled pools' health response:
# SOURCE_POOL=<32-hex-pool-id>; TARGET_POOL=<different-32-hex-pool-id>
m1 -X POST --get \
  --data-urlencode "source_pool=$SOURCE_POOL" \
  --data-urlencode "target_pool=$TARGET_POOL" \
  --data-urlencode 'dry_run=true' \
  "$M1_BASE/noa/v1/maintenance/redistribution/start"
m1 "$M1_BASE/noa/v1/maintenance/redistribution/status"
```

Omit `dry_run` to copy, verify, switch the metadata reference and purge the
unreferenced source. This creates a new destination LINK identity while keeping
the named version unchanged. Topologies can differ; enrolled pool geometry is
never edited. The target must be unsealed. Use `object_key` for one named object,
`fragment` for an explicit scope, or operator-only `all_fragments=true`.
Optional `batch,object_concurrency,pause_millis,bytes_per_second` are bounded by
configured policy. Stops (`POST /maintenance/{kind}/stop`) require an operator
token. `fast_mode=true` is rejected; migration always uses strict durability.

For backups, log in with the **M1 master key** as `secret` for the selected
fragment, requesting read/write/modify/delete, and use the returned access token
as `M1_OPERATOR_TOKEN`. This grants operator authority; sending a raw master key
as Bearer does not. `[metadata_engine] backup_dir` must be configured.

```bash
operator_login=$(jq -n --arg fragment "$M1_FRAGMENT" --arg secret "$M1_MASTER_KEY" \
  '{fragment:$fragment,secret:$secret,read:true,write:true,modify:true,delete:true}' |
  curl --fail-with-body --silent --show-error \
    -H 'Content-Type: application/json' --data-binary @- \
    "$M1_BASE/noa/v1/auth/fragment")
M1_OPERATOR_TOKEN=$(jq -er '.access_token' <<<"$operator_login")
snapshot=$(curl --fail-with-body --silent --show-error -X POST \
  -H "Authorization: Bearer $M1_OPERATOR_TOKEN" \
  "$M1_BASE/noa/v1/maintenance/metadata/backups")
M1_SNAPSHOT=$(jq -er '.id' <<<"$snapshot")
curl --fail-with-body --silent --show-error \
  -H "Authorization: Bearer $M1_OPERATOR_TOKEN" \
  "$M1_BASE/noa/v1/maintenance/metadata/backups"
```

Creation returns HTTP 202 `{"id":"<snapshot>","phase":"running"}`. Listing
returns `product:"M1",component:"metadata_engine",snapshots:[{id,bytes,created_at}],
job:{...},payloads_included:false,download_requires_operator:true`. Poll `.job`
until completed or incomplete, then download `/metadata/backups/{id}/download`.
Completed job fields include `records,bytes,finished_at,capture_mode:"mvcc_snapshot"`.
`POST /metadata/backups/{id}/signed-url` returns a relative `path` and expiry;
resolve it against `M1_BASE` to download without the operator token for 120 seconds.
These are **metadata-only** snapshots. N1 payload backups and coordinated
whole-product recovery follow the [operator guide](../../DOCUMENTATION.md).

## Native named protocol

Use M1's native port with `n1://` or certificate-verified `n1s://`, wire
`n1/0.5`. It uses **M1 frames**, not N1's `Request`/`Command` SDK types. On wire,
write a four-byte big-endian MessagePack-control length, then the MessagePack
map, then exactly `body_len` raw bytes when supplied. The JSON below is a readable
view of the map; `payload` is deliberately a **JSON string**.

```json
{
  "id":"login-1",
  "op":"auth.fragment",
  "payload":"{\"fragment\":\"<alias>\",\"secret\":\"<fragment-key>\",\"read\":true,\"write\":true,\"modify\":true,\"delete\":true}",
  "body":null,
  "body_len":null
}
```

Successful login: `{"id":"login-1","ok":true,"status":null,
"payload":"{\"access_token\":\"<token>\",...}","body":null,
"body_len":null,"error":null}` (payload fields abbreviated here). It authenticates
that connection. `auth.bearer` accepts `{"token":"<access-token>"}`;
`session.info` inspects it. `auth.clear`/`logout` clear the connection;
`auth.logout` with a refresh token revokes the refresh family through M1.

Example raw one-shot frame, immediately followed by five bytes `hello`:

```json
{
  "id":"put-1","op":"upload.one_shot",
  "payload":"{\"object_key\":\"docs/native.txt\",\"content_type\":\"text/plain\",\"durability\":\"strict\"}",
  "body":null,"body_len":5
}
```

| Named operation | Payload / HTTP-equivalent meaning |
| --- | --- |
| `ping`, `auth.fragment`, `auth.bearer`, `session.info`, `auth.clear`, `logout` | Connection controls above |
| `auth.refresh`, `auth.logout` | `refresh_token`; refresh returns replacement credentials; authenticate the connection with the new token explicitly |
| `fragment.create/list/check/hash.public/update/delete` | Same JSON/query fields as fragment routes; update/delete include `fragment` |
| `namespace.list/stat/mkdir/rename/trash/recover` | Corresponding POSIX route fields; `posix.*` aliases retained; `posix.move` aliases rename |
| `object.list`, `trash.list`, `trash.recover_all` | Corresponding object/trash routes |
| `namespace.search`, `namespace.snapshot` | Search scalar query / projection feed |
| `object.metadata` (`object.meta`, `object.stat`), `object.versions` | `object_key`, optional `version_id` where supported |
| `object.get/stream/download` | `object_key`, optional `version_id`; full byte read |
| `object.download_chunk` | `object_key,offset,length`, optional version; bounded chunk read |
| `object.delete/recover/rename`, `object.bulk_delete/bulk_recover` | Same mutation fields as HTTP; dotted `object.bulk.delete/recover` aliases retained |
| `upload.one_shot` (`object.upload.one_shot`) | `object_key,content_type,durability`; raw body |
| `multipart.init` | `object_key,total_size_bytes,expected_parts,part_size_bytes,content_type`; optional `durable,fresh,durability,negotiate_part_size=false` |
| `multipart.put_part` | `version_id,part_index`, optional `durable,durability`; raw body |
| `multipart.status/cancel/list` | Version or list query, optional `durable` |
| `multipart.finalize` | `version_id,session_id`, optional durable and matching init shape |
| `object.archive`, `object.archive_manifest` | Selection JSON / plain line body + scalar format/filename |
| `export.create/status/download/cancel/signed_url` | Selection or `export_id`, signed URL lifetime |
| `capacity.usage/fragment` | Same capacity routes |
| `object.status/repair` | `object_key`, optional health mode |
| `maintenance.health`, `maintenance.pools.health` | Scalar health query fields |
| `maintenance.{gc,repair,redistribution}.{start,status,stop}` | Scalar maintenance query fields |
| `metadata.backups.list/create/download` | No fields / `snapshot` ID for download |

All `multipart.*` operations also accept the `upload.multipart.*` spelling.
Body length/Content-Type and scalar query fields are adapted to the same handlers.
There is no native form-data batch mapping in the current named dispatcher and
no named-native object signed-URL operation; use the HTTP endpoints for these.
Do not infer an operation from a similar N1 name.

Connection controls such as login return JSON in the frame's `payload` string.
Operations forwarded to the named HTTP handlers return their response bytes
after the control frame, including JSON responses: inspect `status`, then read
exactly `body_len` bytes and decode JSON where appropriate. Binary downloads use
the same length-and-raw-bytes framing. Direct
`object.archive` ZIP64/TAR and `object.archive_manifest` TAR responses determine
their exact output length during immutable manifest capture and use this same
streaming path. They do not buffer the archive into the control frame. Final
bytes wait for source verification and pin/manifest cleanup. Other unknown-length
non-JSON responses retain the 8 MiB control-response bound. Control limits are 64 KiB
before authentication, 8 MiB after; native raw upload bodies are at most 1 GiB
per request. A broken/partial exchange requires reconnecting before retry.
Native admission can reject a raw-body upload before consuming its bytes. After
a 429 or another preflight rejection of that exchange, reconnect and authenticate
before retrying; the server closes it to preserve framing. Do not reuse that
connection for the next request.
Canonical frame types are [types.rs](../../metadata_engine/src/server/native/types.rs);
the complete alias/field mapping is [dispatch.rs](../../metadata_engine/src/server/native/dispatch.rs).

## Errors and retries

Application HTTP errors use `{"error":"<message>"}`. Invalid content type,
malformed JSON or extractor failures can use framework text responses; check the
HTTP status before assuming JSON. Native errors use `ok:false` and
`error:{code,message}`; a numeric HTTP error is normally a string code such as
`"403"`, while malformed control payloads can use `"bad_request"`.

| Status | Meaning / client action |
| --- | --- |
| 400 | Invalid geometry, query, unsafe archive path, unsupported operation; fix the request |
| 401 | Missing/expired/invalid credential; refresh once or log in |
| 403 | Permission, operator or fragment-scope denial; do not loop retries |
| 404 | Name/version/upload absent; reconcile the selected identity |
| 409 | Name/immutable-part conflict, unfinished export, occupied job or lifecycle conflict; inspect state |
| 410 | Cancelled upload, expired export, or retired manual permanent/version deletion route |
| 413 | Part/file/body/selection limit; reduce request size or select supported geometry |
| 416 | Unsatisfiable single byte range |
| 422 | Verified staged-payload corruption or request extraction failure; inspect body and integrity state |
| 429 | Shared peer/fragment quota; HTTP includes Retry-After; back off with jitter |
| 500 | Metadata/storage operation failure; retain request identity and inspect service logs |
| 503 | Admission, unavailable dependency/quorum, or unconfigured Accel search; retry boundedly after diagnosis |
| 507 | Object-service capacity/quota exhaustion propagated through M1 |

For multipart, retain version/session and source geometry, query progress after
an uncertain write, and resend only missing **identical** parts. Finalize retries
reuse the same handle/body. A lost namespace-mutation reply requires checking
the source/destination/trash state before repeating it. Do not automatically
repeat a one-shot/batch publication as if it were a deduplicated transaction.
On stream failure, discard the incomplete output or resume a pinned version at
the verified offset; never concatenate a second full response blindly.

This reference does not declare complete RC.2 conformance. Current limitations
remain explicit in [NOA.md](../../NOA.md#current-compliance-boundary) and the
[completion checklist](../RC2-IMPLEMENTATION.md).
