## Native M1 search — November 18, 2026

M1 now serves namespace search without Accel. It searches published live names
by filename, path or extension, with exact, prefix and contains matching.
Pending uploads and trash are excluded. The existing fragment read permission
applies to both HTTP and native requests. See the
[search API and examples](api/M1.md#search-named-objects).

Each request examines at most 4,096 metadata entries plus one lookahead,
through bounded batches and one request-scoped snapshot. A signed cursor binds
the query, scope, result limit and fragment. Searching the entire namespace
can require multiple pages; this is bounded metadata traversal, not an indexed
constant-time substring lookup. An empty page can carry a continuation and
the total remains unknown until it is actually known. Console supports these
pages, preserves existing Accel pagination and discards stale search responses.

N1's executable and runtime source remain unchanged. M1 adds no database
format, secondary index, upload write or retained search session. Existing
Accel search remains optional; fresh unavailable acceleration falls back to
M1. A continuation stays with its original provider, including after restart.

## Monitoring and scan admission — November 18, 2026

The previous M1 reproduces the reported 503 when health and pool controls
concurrently request the same integrity scan. The selected M1 joins an
equivalent running check and returns its progress. An incompatible scope is
409, without admitting another worker. Ordinary monitoring remains read-only
and submits no object-payload I/O.

Health and pool replies expose scoped `integrity_scan` progress. HTTP and native
stop requests drain the current object check before cancellation; unchecked
objects are not marked healthy and confirmed damage remains visible. Scan
state is volatile and a restart does not automatically resume a content scan.
The [API guide](api/M1.md#monitoring-maintenance-and-backups) documents the fields,
scope, stop operation and error semantics.

Cold/stale telemetry retains its observation state instead of becoming a
storage-degradation verdict. M1 allows N1's two-second cold observation to
finish before its own five-second control timeout. A cached pending N1 sample
gets a bounded warm-up retry; healthy/unavailable samples retain the configured
sampling interval. No N1, LINK, ECS Core, database format or mutation path changes.

Console separates cached service readiness from explicit checksum work. It
explains sample cadence and initial pending status, preserves the last health
while refreshing, displays checked/failed/unverified counts and provides Stop.
Routine refresh cannot consume a leftover deep-scan checkbox. Running scan
progress is polled every ten seconds only in the visible Health panel; a late
health response cannot overwrite the serialized scan view.

The separate deep-scan test held upload admission busy. M1 returned
`incomplete` with one deferred version, then `passed` after capacity returned.
Deliberate shard corruption produced `failed` with one failed version.
Concurrent starts joined the active scan. An authorized stop preserved all
object bytes.

One test initially waited for a native N1 write while sending a 256 KiB part
that M1 staged locally. With three data shards and 256 KiB blocks, a full data
stripe is 768 KiB. The corrected test takes its native part size from the pool
layout and retains a separate unaligned staged part. Both cases passed on 3+1
and 2+2. Manually triggered GC deferred the active writer and fenced subsequent
acknowledgements during reclamation.

The live Console exposed a separate GC recovery defect. With M1 online, a
purge during an N1 outage recorded one failure. After N1 restarted, an
explicit retry also failed with HTTP 502 because M1 reused another idle
connection to the stopped process. A two-connection regression test reproduced
this independently. M1 now discards idle connections when a native control
exchange detects a disconnect. The caller receives the failed mutation and
can explicitly retry on a fresh connection. In-flight transfers keep their
connections.
