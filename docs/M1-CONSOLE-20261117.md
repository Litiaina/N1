# M1 RC.1 and Console qualification — November 17, 2026

**The selected M1 passes this service regression. Console now identifies and
monitors M1 and N1 separately while retaining its desktop interface.** No N1,
M1, LINK, ECS Core or database runtime code changes in this stage. Neither a
component release nor a system release is published.

The component targets remain M1 `1.0.0-RC.1`, N1 `1.0.0-RC.2` and system
`1.0.0-RC.2`. M1 uses its own specialized storage crate; ProcyonDB/Fjall is
not the current implementation.

Earlier logs also retain obsolete-label assertions, a relocated Rust harness
with an unavailable compiled-in script path, and two Accel cases missing their
explicit binary setting. Corrected invocations pass. The new launcher's first
optional-Accel check exposed its unsupported `--version` probe; validation now
uses Accel's supported `--help` command. No engine defect or runtime patch is
claimed for those setup failures.

## Console changes

The desktop, wallpaper, logo, taskbar, movable windows and existing applications
remain. A small stylesheet improves title bars, spacing, focus states, responsive
service cards, light-theme contrast and reduced-motion behavior. No framework,
new UI dependency, health polling interval or automatic deep scan is introduced.

Monitoring labels the metadata service **M1** and LINK object storage **N1**.
Each retains its own node, endpoint, CPU, RAM, process RSS, open files and
storage observations. An overview summary uses the same cached snapshot;
missing telemetry remains unavailable. M1 backup controls explicitly identify
the master-key field and snapshot actions. GC/healing/migration retain visible
job results and the server's configured policy. N1 object backups remain
separate from M1 database snapshots.

The owned local launcher now starts the independent engines with distinct INI
and environment files, separate JWT/master credentials, a private CA and
verified Console → M1 → N1 TLS. It creates no fragment by default. An explicit
Office-fixture flag is available. Optional Accel binds loopback and uses M1
as its authoritative backend. Restart preserves the same database and pool
identities; no system service or trust-store change is installed. The default
single-member fixture has no disk redundancy; two fresh independent member
paths select 1+1.

`metadata_engine/tests/noa_service/console_workflows.mjs` is Playwright test
automation invoked by Rust. It is not an engine module or production request
path. Its two changed assertions follow the M1-labelled snapshot controls.
Browser tests use JavaScript because they exercise the browser DOM; engine
workloads, recovery checks and independent data assertions remain Rust.

## Scope and reproduction

Use the existing commands with disposable explicit storage roots:

```sh
cargo test --release -p m1 -p m1_storage -p n1_native_client \
  --all-targets --offline --locked -- --test-threads=4
cargo clippy --release -p m1 -p m1_storage --all-targets \
  --offline --locked -- -D warnings
```

Console's [verification guide](https://github.com/Litiaina/console/blob/main/TESTING.md)
documents the Node, browser, filesystem-root and launcher settings. Private
evidence retains raw logs, original failures, source checkpoints and screenshots.
Generic visual-review fixtures are distinguished from real-service screenshots.

No existing million-object population is restarted or replaced. This stage does
not perform another physical power cut, reclassify prior cut windows, establish
new throughput/p99 measurements or claim complete field-level NOA conformance.
Final pairing/packaging and the required contract/operator acceptance remain
governed by the [release checklist](RC2-IMPLEMENTATION.md). N1 stays frozen.
