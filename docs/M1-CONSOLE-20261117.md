remain. A small stylesheet improves title bars, spacing, focus states, responsive

new UI dependency, health polling interval or automatic deep scan is introduced.

Monitoring labels the metadata service **M1** and LINK object storage **N1**.

single-member fixture has no disk redundancy; two fresh independent member
paths select 1+1.

`metadata_engine/tests/noa_service/console_workflows.mjs` is Playwright test
automation invoked by Rust. It is not an engine module or production request
path. Its two changed assertions follow the M1-labelled snapshot controls.
Browser tests use JavaScript because they exercise the browser DOM; engine
workloads, recovery checks and independent data assertions remain Rust.

## Object Status correction

A subsequent Console regression reproduces a presentation error against these
same binaries: the old panel converts N1's missing-shard index array `[0]` to
the number zero and reads aggregate fields absent from the LINK response.
The corrected Console uses nested EC geometry, counts shard lists, distinguishes
header presence from explicit checksum verification and fetches fresh health
after repair. Neither engine's runtime or API changes.

The new ignored Rust case
`object_status::console_object_status_matches_link_health_and_verifies_repair`
owns an isolated two-HDD 1+1 fixture. It removes shard zero, requires the browser
to show that missing shard and repair it, then checks exact rebuilt shard bytes
and original-version readback independently. The old Console fails the display
assertion; the corrected build passes. Nine new Node checks and 35 new browser
executions pass; the wider selected browser run totals 76 passes and 64
conditional skips. Original attempts remain in private evidence. The local
Console update retains both running engine processes and existing user data.

## Native M1 search — November 18, 2026

M1 now serves namespace search without Accel. It searches published live names
by filename, path or extension, with exact, prefix and contains matching.
Pending uploads and trash are excluded. The existing fragment read permission
applies to both HTTP and native requests. See the
[search API and examples](api/M1.md#search-named-objects).

Each request examines at most 4,096 metadata entries plus one lookahead,
through bounded batches and one request-scoped snapshot. A signed cursor binds
the query, scope, result limit and fragment. Searching the entire namespace
can require multiple pages; this is bounded metadata traversal, not an indexed
constant-time substring lookup. An empty page can carry a continuation and
the total remains unknown until it is actually known. Console supports these
pages, preserves existing Accel pagination and discards stale search responses.

N1's executable and runtime source remain unchanged. M1 adds no database
format, secondary index, upload write or retained search session. Existing
Accel search remains optional; fresh unavailable acceleration falls back to
M1. A continuation stays with its original provider, including after restart.
