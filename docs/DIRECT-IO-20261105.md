# Aligned LINK upload I/O — November 5, 2026

LINK large uploads now retain N1's aligned `O_DIRECT` path, using the existing
ECS `AlignedBuffer` and owned io_uring/blocking backend. Objects below 1 MiB
keep buffered writes. No configuration change is required.

The immutable shard format stays unchanged. A writer carries partial pages
between encoder groups and sends complete aligned pages through a separate
direct descriptor for the same existing staging inode. Only each part's
unaligned ends are buffered. Neighboring parts can share a buffered boundary
page; neither direct range overwrites that page. There is no read-modify-write,
new receipt, format/profile change or additional persistence barrier.

The direct open is descriptor-relative, NOFOLLOW, existing-only and checked
against the buffered inode. It never creates or truncates an upload. The
existing key lifecycle, checksum policy, admission/memory controls, cancellation
ownership and durability barriers remain in force. Direct errors fail the
request without buffered replay.

## Qualification

- Full workspace: **474 passed, 0 failed**, 37 explicit opt-in/helper exclusions.
- Documentation: **81 passed**; scoped strict all-target Clippy passed.
- Three direct-I/O cases passed independently on each XFS HDD, including
  concurrent neighboring parts, retries/restart and a `mincore` check proving
  that interior payload pages bypass the cache before exact reopened readback.
- Five existing HDD persistence cases, eleven purge cases and thirteen selected
  two-HDD metadata/object integration scenarios passed. The native release
  witness validates written staging frames before SIGKILL/SIGTERM, rather than
  interrupting a source that only filled the encoder. The 514-part ACK/resume
  test also passed after both services were killed.
- **24 full benchmark trials** passed **1,648 exact length/SHA-256 downloads**,
  clean owned-server shutdowns and purge inventories. Repeated hardware runs
  are not additional distinct tests.

All datasets, binaries and reports use `/mnt/HDD1TB001` and `/mnt/HDD1TB002`;
temporary functional fixtures use RAM. The comparisons are standalone native
object-engine workloads, with no metadata/Console process in the timed path.
Both configure 1+1 EC, 256 KiB blocks and required io_uring. Each pair uses
balanced trial order and fresh private directories on the same two XFS HDDs.

## Measurements

| Workload | Before | Direct LINK | Time change |
| --- | ---: | ---: | ---: |
| Focused 1 GiB durable PUT: buffered LINK → direct | 11.903 s | 10.141 s | −14.81% |
| Focused 1 GiB durable PUT: original NCX → direct | 9.996 s | 9.071 s | −9.26% |
| Mixed 1 GiB PUT: buffered LINK → direct | 10.456 s | 8.708 s | −16.72% |
| Mixed 100 × 4 KiB sequential PUT | 29.468 s | 28.861 s | −2.06% |
| 100 × 4 KiB batch Begin + body | 0.829 s | 0.902 s | +8.76% |
| Standard 256 MiB multipart, timed phase sum | 5.202 s | 3.432 s | −34.03% |
| Durable 256 MiB multipart, timed phase sum | 20.716 s | 12.369 s | −40.29% |
| 100 concurrent normal PUT, 16 clients | 11.617 s | 11.382 s | −2.03% |

Multipart sums include Begin, parts, reconnect/status, finalize and repeat;
shared verification/delete are separate. They are sums of timed phases, not
continuously measured whole-job wall times. Small-object HDD timings vary
substantially; these trials do not establish equivalence or confidence intervals.

The focused buffered-LINK pair used **4.693 → 5.230 CPU seconds** for PUT and
**34.46 → 35.86 MiB** maximum process RSS HWM. Against NCX, the separate focused
pair used **4.823 → 4.385 CPU seconds** and **49.40 → 35.21 MiB** HWM. Campaign
windows are separate; their CPU/speed ratios must not be pooled.

Direct writes avoid populating interior cache pages. Immediate post-upload GET
and explicit shard-validating status therefore cost disk reads where the
buffered baseline often reads cache: focused post-write GET was **1.083 →
8.123 s**, while warm GET was **1.089 → 1.074 s**. Named metadata resume remains
indexed without object reads. The detailed report retains these costs, the
slower batch sample and every other adverse row; no universal improvement or
cold-cache comparison is claimed.
